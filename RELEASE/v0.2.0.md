# RELEASE v0.2.0: Asset Pipeline and Minimal Animation

**Status:** active
**Exit gate:** idle, running-right, failed play from converted Big Blue Fish frames
**Depends on:** v0.1.0
**Requirements:** R-C1, R-L1

## Scope

`tools/convert-assets.py` (FFmpeg libvpx-vp9 + Pillow) with the state table `tools/state-map.json`: WebM dir -> `assets/big-blue-fish/frames/<state>/NN.png` (<= 8 frames, 192x208, shared crop box so frames do not jitter, alpha kept), a merged `frames-manifest.json`, and `pet.json` (source file, frame count, original resolution, list of unmapped clips). States: idle, running-right, failed, plus `running` (same clip, because the hook `state_map` sends PreToolUse to `running`). Run with `make convert-assets`. The renderer takes PNG frame folders, not a sprite sheet, so the PRD's 1536x1872 check is replaced by per-frame 192x208 checks. Idle memory <= 120 MB.

## Built

Verified (2026-11-06, macOS arm64):
- `make convert-assets` converts 4 states (idle, running-right, failed, running), 8 frames each, 192x208, from the real 1280x720 VP9-alpha clips; alpha kept (contact sheet checked by eye). `pet.json` lists 3 mapped clips and 103 unmapped (106 total; the earlier "212" counted `.mask` files).
- `make check` green: 8 ACs with 2 tests each, 6 AC0.2 Rust tests, 4 converter Python tests, upstream tests.
- Rebuilt app loaded 61 frames; piping `PreToolUse` then `Stop` into `pet-hook.sh claude-code` logged `state=running` then `state=jumping`. `.dmg` is 3.5 MB; idle RSS about 109 MB (budget 120 MB for 0.2.0).
- Removing the Windows scripts earlier broke 5 upstream hook tests that read them; I deleted those tests.

Limits: the fish animation itself was not watched (no screen capture); `StopFailure` produced no state line in the log, so the `failed` row is converted but not seen switching (0.3.0 maps it); `idle` loops at 7 fps with 3-tick holds (2.4 s), unjudged by eye; shared crop box makes the fish smaller in clips with props.
