# RELEASE v0.8.7: release no longer diverges from main

**Status:** active
**Exit gate:** `make release VERSION=x.y.z` pushes with no rebase step, and CI never commits to main
**Depends on:** v0.8.6
**Requirements:** R-D1

Packaging and release-flow fix: no AC change, no behaviour change.

## What failed

Since v0.8.5 the release workflow's `homebrew` job committed `Casks/deepseek-pet.rb` back to `main` after every tag. `make release` amends HEAD and pushes, so the next release was always rejected (`fetch first`, then `non-fast-forward`). It broke at v0.8.5 and again at v0.8.6. The sibling Rust projects never push from CI to main.

## Fix

- `make bump` rewrites the `version` line of `Casks/deepseek-pet.rb`; `make release` commits it with the tag, like `Cargo.toml`.
- The cask uses `sha256 :no_check`: the dmg is built by CI after the tag, so its hash cannot be in the tagged commit. Trade-off: no checksum pin on the dmg (the download is still HTTPS from GitHub Releases; `SHA256SUMS` stays on each release).
- The `homebrew` job, `packaging/homebrew/` and `scripts/update-cask.sh` are removed.
- The `git pull --rebase` line suggested earlier for the Makefile is not needed and is not added.
