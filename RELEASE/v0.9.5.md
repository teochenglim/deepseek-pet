# RELEASE v0.9.5: statusline removed, Show Claude context reads the transcript and speaks in the pet's bubble

**Status:** active
**Exit gate:** no statusline code or menu row remains, Show Claude context shows the context in the pet's speech bubble and the pet stays visible, and `make check` is green
**Depends on:** v0.9.4
**Requirements:** R-X1

No new dependency (`serde_json` keeps the `preserve_order` feature added in 0.9.0, now used by the cleanup).

## What

- **Statusline removed.** The avatar status line, its install row in Install hooks, the `--statusline` printer, the avatar generator (`tools/make_statusline_logo.py`), `scripts/statusline-preview.sh` and the Makefile targets are gone.
- **Old installs are cleaned up** (`legacy.rs`): the app still answers `--statusline` (prints nothing and exits, so Claude Code refreshing an old setting never opens a second pet) and on launch removes its own `statusLine` entry from `~/.claude/settings.json` (backup `settings.json.deepseek-pet.bak`, key order kept) and the `~/.deepseek-pet/bin/statusline` link. A status line of the user's own is never touched.
- **Show Claude context needs nothing installed.** `context.rs` reads the tail of the newest `~/.claude/projects/*/*.jsonl` and takes the last assistant line's usage (input, cache read, cache write, output). The window size is assumed and shown as `~200k`: 1M if the model name has `1m` or more than 200k are already in use, else 200k.
- **It speaks like the welcome bubble.** The text appears in the pet's speech bubble (the one that says "准备好了～" on start). The pet used to vanish because the window is only about 60 px taller than the pet, so a multi-line bubble pushed the sprite out of it. `note_window.rs` now grows the window up and sideways while the note shows (the pet's centre and bottom edge stay fixed) and restores it when the note ends, is replaced, or is clicked away; if you dragged the window meanwhile it shrinks back from where it is.

## Limits

- Not exercised in a real session: the bubble layout, the window growing and restoring, and the pet staying visible need a manual look (menu bar > Show Claude context, with a Claude Code session that has sent a message). The window geometry maths is tested; the JS and CSS are not.
- The window size (200k or 1M) is a guess: a 1M-window conversation that holds under 200k tokens and whose model name has no `1m` shows a percentage of 200k, too high (the Sonnet 5.5 screenshot showed a 1M window with no marker in the name). Tokens used are exact; the `~` marks the guess.
- Transcripts are a Claude Code implementation detail; a format change would show "No Claude context yet" until updated.
- A note taller than the space above the pet window on screen is clipped by the screen edge.
