# RELEASE v0.7.0: Map animations to hook events

**Status:** active
**Exit gate:** from the menu-bar icon you can choose, for Claude Code and Z.ai ZCode, which animation each hook event plays, and the choice survives a restart
**Depends on:** v0.6.1
**Requirements:** R-K1

## What you get

Today the event-to-animation table is fixed in `config.example.json` (`PreToolUse` shows `running`, `Stop` shows `jumping`, `PostToolUseFailure` shows `failed`, and so on). In this release the menu-bar icon lets you change any row.

```
Menu-bar icon
 +-- Map animations
      +-- Claude Code
      |    +-- PreToolUse        (shows: Running)
      |    |    +-- Default
      |    |    +-- State  > Idle | Running | Waiting | Review | Failed | Waving | Jumping
      |    |    +-- Clip   > <category> > <clip>      (the 106 clips)
      |    |    +-- Assign last played clip
      |    |    +-- No animation
      |    +-- PostToolUse ... Stop ... StopFailure ... PermissionRequest ... (every event the agent sends)
      +-- Z.ai ZCode        (same, with ZCode's own events, for example PostToolUseFailure)
      +-- Reset all to defaults
```

Two kinds of choice:
- **State** replaces the animation the pet shows while that event is the latest one (what happens today, but chosen by you). It takes part in the priority rules (waiting beats running beats idle, failed lowest).
- **Clip** plays one clip once when the event arrives and leaves the pet's state alone, so a long task keeps its working animation. Good for "play the dance when `Stop` fires".

"Assign last played clip" is the shortcut: play clips from the right-click menu until you find one you like, then assign it to an event in two clicks, instead of walking four menu levels (agent, event, category, clip).

## Scope

- `~/.deepseek-pet/mapping.json`: `{"version": 1, "agents": {"claude-code": {"Stop": {"clip": "c042"}, "PreToolUse": {"state": "review"}}, "zai": {...}}}`. Absent keys use the defaults in `config.example.json`. A missing, empty or invalid file is ignored (defaults), never a crash.
- Hook scripts (`common.py` `resolve_state`) read the mapping on every event, so changes apply immediately with no restart. Payload gains an optional `clip` field.
- Backend and renderer: a payload with `clip` triggers `playExtra` (as the Play animation menu does) without changing the aggregated state.
- Tray menu built from the mapping and the catalog, check marks on the current choice, rebuilt after each change. Choosing something also previews it once.
- Event lists per agent come from one table (`tools/agents.json`) that 0.8.0 extends.

Out of scope: agents other than Claude Code and ZCode (0.8.0), per-project mappings, editing dialogue bubble text, looping clips.

## How it behaves (as built)

- Menu path: Map animations, agent, event, then Default / State / Clip / Use last played / No animation. The event's submenu title shows the current choice (`PreToolUse  (Thinking)`); check marks show it inside. The whole tray menu is rebuilt after each change.
- State choices offered: Idle, Running, Waiting, Thinking, Failed, Waving, Jumping. The event keeps its default dialogue text.
- Clip: plays once on the live event socket. The state stays the event's default (a working fish keeps working); if the default is a one-shot (Stop shows jumping), the clip replaces it and the pet goes idle afterwards.
- No animation: the event sets the pet to idle.
- Choosing a clip previews it immediately. Choosing a state does not preview.
- Events from the sessions-folder watcher (used when the socket cannot bind) update state but do not replay clips.
- `mapping.json` is `~/.deepseek-pet/mapping.json` (or `$DEEPSEEK_PET_HOME`), in dev runs too; written atomically with a one-time `.bak`.

## Notes and risks

- The agent event lists are not identical: Claude Code has `StopFailure`, ZCode has `PostToolUseFailure`. The menu shows only events the agent really sends.
- A native menu with agents x events x categories x clips is deep; "Assign last played clip" exists to avoid using it.
- `mapping.json` is the user's data: write it atomically and keep a `.bak` like the hook installer does.

## Built

Verified (2026-11-06, macOS arm64): `make check` and `make audit` green with 32 ACs (Rust mapping model and menu-id tests, Python hook tests run from Rust by name, aggregator clip-channel tests).
Live run of the built `.app` with a temp `DEEPSEEK_PET_HOME` and this `mapping.json`: Claude `PreToolUse` set to Thinking, Claude `Stop` set to clip `c042`, ZCode `PostToolUseFailure` set to No animation. Hook events from the installed copy of `pet-hook.sh` gave: PreToolUse shows `review` (default is `running`); Stop plays clip c042 (`play-animation c042 ok=true`) and leaves the pet idle instead of jumping; PostToolUseFailure shows idle instead of failed; an unmapped ZCode PreToolUse still shows `running`. The tray menu with about 2,500 items (2 agents x 18 events x 106 clips and states) builds in 34 ms; idle RSS about 100 MB.
Limits (not done by hand): clicking through the Map animations menu, the check marks and title suffixes after a change, "Use last played clip", Reset all to defaults, and the menu rebuild after a click; a real Claude Code or ZCode session with a mapping set; the Homebrew install.
