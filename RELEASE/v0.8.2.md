# RELEASE v0.8.2: Varied default animations

**Status:** active
**Exit gate:** a Claude Code turn with several tool calls shows different Work clips, not only head turning
**Depends on:** v0.8.0
**Requirements:** R-K1

## Why

Every default event mapped to one of the 8 states, and most of those clips are the fish turning its head (pacing, looking around). A long agent turn looked the same all the time.

## What changed

Entries in `config.example.json` `state_map` take an optional `clips` list. The hook picks one at random and the pet plays it once, then settles on the entry's `state` as before. A menu choice in `mapping.json` still wins, so "Map animations" is unchanged.

| Event | State (unchanged) | Random pool |
|---|---|---|
| PreToolUse, SubagentStop, PostCompact (working) | running | Writing code, Busy tapping, Sorting and filing, Briskly taking notes, Eating tokens |
| UserPromptSubmit, PreCompact (thinking) | review | Thinking bubbles, Deep-thinking mutter |

`Pacing and looking around` (c052) is kept out of the working pools; it stays the `waiting` state for approvals.

A pick fires at most once per 11 s (`.last-default-clip-<source>` next to the sessions folder), because a clip lasts about 10 s and a burst of tool calls would otherwise restart a new clip on every call.

`config_version` is now 3, so an existing `config.json` gets the new `state_map` once (with `.bak`, as in 0.8.0). Any hand edit of `state_map` is replaced; per-event menu choices are not.
