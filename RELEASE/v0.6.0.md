# RELEASE v0.6.0: Play any animation by hand

**Status:** active
**Exit gate:** all 106 Big Blue Fish clips can be played from the menu-bar icon, without slowing startup
**Depends on:** v0.5.0
**Requirements:** R-M1, R-I1, R-P1

## Scope

- **Menu-bar icon, Play animation submenu.** Clips are grouped into eight categories (Click reactions, Work, Balance, Muttering, Meals and snacks, Festivals, Play and hobbies, Moods and movement, Magic and animals) with English titles; the original Chinese name is kept in the catalog. "Random animation" picks one. Choosing a clip shows the pet if hidden and plays the clip once, then the pet returns to what it was doing (a working fish keeps working; a permission request mid-clip takes over).
- **On the floating pet too, with no extra click.** Right-clicking the pet opens one native macOS menu at the cursor: Random animation, the category submenus, then Hide for now and Quit. 106 clips do not fit in the pet's small window, and a native menu needs no extra window. If the native menu cannot open, the old in-window Hide/Quit menu is the fallback. Tray and popup share one set of actions (`menus.rs`); their menu ids use different prefixes (`play:c001` and `pop:play:c001`) so a click is handled once.
- **All 106 clips converted** (`make convert-extras`, `tools/convert-assets.py --extras`): 16 frames each at 8 fps (about 2 s), palette PNGs of about 11 KB instead of 50 KB, written to `assets/big-blue-fish/frames/extras/<id>/NN.png` with `extras/catalog.json` (`tools/clip-titles.json` holds titles and categories).
- **On demand, not at startup.** Extras are not in `frames-manifest.json`; the renderer loads a clip's 16 frames when it is chosen and frees them when it ends (`SpriteAnimator.playExtra` / `releaseExtra`). Startup still loads only the nine core states.
- Trivy fix (CI): `tools/requirements.txt` pins `pillow==13.0.0`; 11.3.0 carried 40 HIGH/CRITICAL CVEs and failed the security scan.

Out of scope: a command-line trigger, searching the 106 clips, looping or stopping a clip early, per-clip speed.

## Notes

- The popup blocks the main thread while it is open (macOS menu tracking); the pet freezes for that moment only.
- Choosing a clip emits a `play-animation` event with `{id, frames, fps}`; hit-testing uses the clip's own alpha masks.
- Quantising to 128 colours is visible only as slightly flatter shading; checked on a contact sheet of eight clips.
- The mapped state clips (idle, running, and so on) also appear in the menu, so every one of the 106 can be seen.

## Built

Verified (2026-11-06): `make check` green with 23 ACs (extras, tray menu wiring, 5 Node cases on the real `SpriteAnimator`, catalog unit tests); local `trivy fs` (CRITICAL/HIGH) reports 0 for npm, cargo and `requirements.txt` after Pillow 13.0.0 (11.3.0 had 40); the rebuilt app starts, still loads only 72 frames, idle RSS about 103 MB; extras are 21 MB on disk, dmg unchanged at 5.9 MB.

**Known gap (found while checking, not fixed here):** the `.app` and `.dmg` do not contain the frames. `DeepseekPet.app/Contents/Resources` holds only `icon.icns`; the pet finds `assets/` by walking up from the executable to this repository, so a copy installed in /Applications or via Homebrew would show no animation. The same applies to the 106 extras. Needs its own release (bundle the frames as resources and resolve `frames_dir` from the app's Resources folder).
Limits: not clicked or watched: submenu appearance with 106 items, every clip playing, memory after many plays, hit-testing during a clip.
