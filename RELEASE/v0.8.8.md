# RELEASE v0.8.8: working animations end when the agent goes quiet

**Status:** active
**Exit gate:** a looping working animation (thinking / tools) returns to the default idle fish once events stop, and `make check` is green
**Depends on:** v0.8.7
**Requirements:** R-K1

## What failed

`running` and `review` (and the clips played from them) loop until a later event changes the state. `Stop` does that normally, but an interrupted turn (Esc), a killed agent or a dropped hook sends no `Stop`, so the fish kept swimming "Working..." until the 1 h session-file TTL.

## Fix

- Renderer watchdog in `animator.js`: entering `running` or `review` arms a 90 s timer (`WORKING_TIMEOUT_MS`); every new state event re-arms it (each tool call fires a hook), so a live agent never times out. On expiry the pet goes back to `idle` and the bubble is cleared.
- `Stop`, `waving`, `failed` and `waiting` cancel it: an approval prompt may legitimately wait for a human longer than 90 s.
- Clips from the Play menu and hook `clips` already play once and return; unchanged.
- No new dependency, no hook protocol change.

## Limits

A single tool call or thinking pass with no hook event for over 90 s drops to idle until the next event. Raise `WORKING_TIMEOUT_MS` if that bites. Not exercised on a real agent; needs a manual pass (start a turn, press Esc, expect idle after about 90 s).
