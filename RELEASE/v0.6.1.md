# RELEASE v0.6.1: A standalone app

**Status:** active
**Exit gate:** `DeepseekPet.app` copied to /Applications (or installed with Homebrew) on a machine without this repository shows the pet, plays its clips, and installs hooks
**Depends on:** v0.6.0
**Requirements:** R-D1

Patch release, no new features. Found while checking v0.6.0: `DeepseekPet.app/Contents/Resources` holds only `icon.icns`. The app finds `assets/`, `config.json`, the hook scripts and `runtime/` by walking up from the executable to this repository (`config.rs` `detect_repo_root`), so an installed copy has no animations. v0.7.0 and v0.8.0 write hook configs that point at scripts, so they need this first.

## Scope

- Bundle `assets/big-blue-fish/frames` (about 25 MB with extras), `config.example.json` and the hook scripts as Tauri resources.
- Resolve frames, default config and hook scripts from the app's Resources folder when running from a `.app`; keep the repo walk for `make run`.
- Move user state (`config.json`, `runtime/sessions`, the event socket, later `mapping.json`) to `~/.deepseek-pet/`.
- Hook installs point at the copy of `pet-hook.sh` inside the app (or a stable copy under `~/.deepseek-pet/hooks/` so moving the app does not break them).
- Decide whether hook scripts keep needing `/usr/bin/python3` (a stub that asks for the Xcode tools on a clean Mac) or are ported to Rust or shell.

## Notes

- Layout: `Contents/Resources/{assets/big-blue-fish/frames, config.example.json, hooks/}` (read-only) and `~/.deepseek-pet/{config.json, hooks/, runtime/sessions/}` (writable). `DEEPSEEK_PET_HOME` overrides the folder.
- Hook scripts live at `~/.deepseek-pet/hooks/pet-hook.sh`, a path that does not change when the app is moved or updated. Install them with `python3 ~/.deepseek-pet/hooks/install_hooks.py install --hook-script ~/.deepseek-pet/hooks/pet-hook.sh` (a menu-bar item for this comes in v0.8.0). Hooks installed from the repo (`scripts/install-hooks.sh`) point at the repo copy instead; running either installer replaces the other's entries.
- `config.json` is created once from the bundled default and then left alone, so a later app version's new default `state_map` does not reach existing users; v0.7.0's `mapping.json` avoids that for animation choices.
- The hook scripts still need `/usr/bin/python3`, which on a clean Mac triggers the Xcode command line tools prompt. Not solved here; v0.8.0 plans to move the installer into the app, and the scripts themselves can follow.

## Built

Verified (2026-11-06, macOS arm64):
- `make check` green: 27 ACs; `make audit` green.
- The built `DeepseekPet.app` now carries 26 MB of resources (frames with all 106 clips, `config.example.json`, hook scripts, `install_hooks.py`); the dmg grew from 5.9 to 27.4 MB.
- Standalone run: the `.app` was copied to a folder outside the repository and started with `DEEPSEEK_PET_HOME` pointing at a temp folder. It created `config.json`, `hooks/` and `runtime/sessions/` there, loaded all 72 startup frames from `Contents/Resources/assets/big-blue-fish/frames`, and `~/.deepseek-pet/hooks/pet-hook.sh claude-code` events (copied hook, not the repo's) moved the pet to running and then waiting. Your real `~/.deepseek-pet` was not touched.

Limits: not tested on a second Mac or with the repository removed from disk (the copy simply sat outside it); the Play animation menu was not clicked in the standalone copy, so the extras path is covered only by the bundle contents test and the frames-dir logic; Homebrew install untested; the hooks still need `/usr/bin/python3`; in that run the event socket did not bind because my temp path was too long for a Unix socket, so events arrived through the sessions folder watcher (the default `/tmp/kotori-pet.sock` is short enough).
