# RELEASE v0.8.9: recover from a stuck Homebrew tap

**Status:** active
**Exit gate:** a user whose tap clone holds merge-conflict markers can recover with the documented commands, and `make check` is green
**Depends on:** v0.8.8
**Requirements:** R-D1

Docs-only fix: no AC change, no behaviour change.

## What failed

`brew install --cask teochenglim/deepseek-pet/deepseek-pet` failed with `Cask 'deepseek-pet' is unreadable ... 1: <<<<<<< HEAD`. The user's tap clone (`$(brew --repository)/Library/Taps/teochenglim/homebrew-deepseek-pet`) was stuck mid-rebase (`UU Casks/deepseek-pet.rb`, `HEAD (no branch)`). Cause: v0.8.5 and v0.8.6 CI committed the cask back to `main`, so the tap held a commit (`cask: deepseek-pet v0.8.6`) that conflicted with the real history once `brew update` pulled. v0.8.7 removed that commit, but a clone already in the conflicted state does not heal itself.

## Fix

- README Install: a short recovery block (`brew untap`, tap again by URL, install). The tap is a read-only mirror of this repo, so nothing local is lost.
- No change to `Casks/deepseek-pet.rb`; it is clean on `main`.
