# RELEASE v0.8.0: More agents, one active source, better default animations

**Status:** active
**Exit gate:** from the menu-bar icon you can install and remove the pet's hooks for each supported coding agent, map animations for the ones you installed, choose which one drives the pet, and the pet keeps moving sensibly while two agents run at once
**Depends on:** v0.7.0
**Requirements:** R-K2, R-K1

## What you get

```
Menu-bar icon
 +-- Big Blue Fish v0.8.0     (greyed: which build is running)
 +-- Map animations           (only agents whose hooks are installed)
 +-- Active source            (All sources / Claude Code / ZCode ...: the one that drives the pet)
 +-- Install hooks
 |    +-- Claude Code          [installed]    click to remove
 |    +-- Z.ai ZCode           [installed]
 |    +-- Codex CLI            [not installed] click to install
 |    +-- Gemini CLI
 |    +-- Qwen Code
 |    +-- Kimi Code
 |    +-- GitHub Copilot CLI
 |    +-- Cursor CLI
 |    +-- OpenCode
 |    +-- DeepSeek Harness
 +-- Quit
```

**Why the Active source:** with Claude Code and ZCode both running, the pet shows the highest-priority state of all sessions, so one agent waiting on an approval (or a session that never sent its last event) keeps the pet on `waiting` while the other works. Picking one source makes only its sessions count. The others keep reporting and show again the moment they are selected. Default stays "All sources". The choice is saved in `~/.deepseek-pet/settings.json`.

**Better default animations** (`config.example.json`; an existing `config.json` below `config_version` 2 gets the new `state_map` once, with a `.bak`):

| Event | Before | Now | Why |
|---|---|---|---|
| UserPromptSubmit | running | **review** (Thinking) | the agent is thinking before it acts |
| PreToolUse / PostToolUse | running | running | working |
| PreCompact | waiting | **review** (Thinking) | compacting is the agent's own work; `waiting` outranks everything and looked like a stall |
| PostCompact (new) | none | **running** | compaction done, work resumes |
| SubagentStop | idle | **running** | a subagent finishing does not end the main turn; idle froze the pet mid-turn |
| Stop | jumping | jumping | done |
| PermissionRequest / QuestionAsked | waiting | waiting | the only states that really wait for the user |

A greyed entry means the agent's config folder was not found on this Mac. Clicking toggles install or removal and the label updates.

## Agent formats (from each tool's documentation, 2026-11-06; verify against the installed version while building)

| Agent | Config file | Hook shape | Notes |
|---|---|---|---|
| Claude Code | `~/.claude/settings.json` | `hooks.<Event>[] {matcher?, hooks:[{type:"command", command}]}` | done in 0.3.0 |
| Z.ai ZCode | `~/.zcode/cli/config.json` | `hooks.enabled` plus `hooks.events.<Event>[]` | done in 0.3.0; ignores project-level hooks |
| Codex CLI | `~/.codex/hooks.json` or `[[hooks.<Event>]]` in `config.toml` | same nesting as Claude Code | hooks must be reviewed and trusted in `/hooks` the first time; the app must say so after installing. Upstream code already has Codex support to reuse |
| Gemini CLI | `~/.gemini/settings.json` | `hooks.<Event>[] {matcher?, hooks:[{type:"command", command}]}` | events `BeforeTool`, `AfterTool`, `SessionStart`, `SessionEnd`, `BeforeAgent`, `AfterAgent`, `Notification`; session id arrives as `GEMINI_SESSION_ID` |
| Qwen Code | `~/.qwen/settings.json` | Claude-style, plus `disableAllHooks` | a reported 0.21.x regression dispatches only `UserPromptSubmit` and `Stop`; global hooks were ignored in 0.15.x. Check the installed version |
| Kimi Code | `~/.kimi-code/config.toml` | `[[hooks]]` with exactly `event`, `matcher`, `command`, `timeout`; any extra field makes the file fail to load | TOML needs a careful editor so the user's comments survive |
| GitHub Copilot CLI | `.github/hooks/*.json` (repo) and a user-level hooks file | `{"version":1,"hooks":{"preToolUse":[{"type":"command","bash":"...","timeoutSec":N}]}}` | camelCase events (`sessionStart`, `userPromptSubmitted`, `preToolUse`, `postToolUse`, `agentStop`, `sessionEnd`); payload uses `toolName` |
| Cursor CLI | `~/.cursor/hooks.json` | `{"version":1,"hooks":{"stop":[{"command":"..."}]}}` | CLI support is partial and reports conflict on whether `stop` and `sessionStart` fire; test per version |
| OpenCode | plugins folder | plugin file, not a JSON hook | upstream already ships `opencode-plugin.ts` |
| DeepSeek Harness (`dsh`) | none | no native hook format found; its `hooks-claude-code` and `hooks-codex` plugins run existing Claude Code or Codex hook files | **decided:** listed as a greyed row "runs your Claude Code hooks, nothing to install"; install Claude Code's and Harness sessions appear as `claude-code` |

Sources: [Gemini CLI hooks](https://geminicli.com/docs/hooks/), [Cursor hooks](https://cursor.com/docs/hooks), [Copilot hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference), [Qwen Code hooks](https://qwenlm.github.io/qwen-code-docs/en/users/features/hooks/), [Kimi Code hooks](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html), [Codex hooks](https://www.codex-docs.com/en/docs/hooks), [DeepSeek Harness CLI](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/README.md).

## Scope

- **Installer in the app.** The bundled `install_hooks.py` is the helper (the hook scripts already need `/usr/bin/python3`); the menu runs it. Without the Xcode command line tools the stub python would open an install dialog, so the menu checks `xcode-select -p` first and shows what to run instead. Same guarantees as 0.3.0: idempotent, our entries marked, foreign hooks untouched, one-time `.bak`, invalid JSON/TOML never overwritten, uninstall removes only ours.
- **One adapter per agent** that turns the agent's event names and payload into the pet's events: `BeforeTool` becomes `PreToolUse`, Copilot `preToolUse` and `toolName`, Cursor `stop` with `status` (`error` becomes the failed state), Gemini session id from the environment. Table-driven: `desktop/cross-platform/hooks/agents.json` (config path, format, events, native event names) is read by the installer, the hook scripts and the Rust menus, so adding an agent is mostly a data change.
- **Mapping for every installed agent** with the 0.7.0 menu, showing only the events that agent can send.
- **Detection and state in the menu:** installed or not, and a note when the agent needs an extra step (Codex trust review, restart the session).
- Version checks where the docs disagree (Qwen, Cursor): warn instead of silently installing hooks that never fire.

Out of scope: Windows, project-level installs (user-level only), editing an agent's other settings, agents not listed.

## Notes and risks

- Hook formats move quickly and several are young (Cursor CLI, Qwen Code, Kimi Code, DeepSeek Harness). Every writer is covered by tests against sample files, but the first release should label each agent with the version it was checked against.
- DeepSeek Harness may have nothing to install natively; decide before building.
- Installing into other tools' config files is the riskiest thing the app does: back up first, never overwrite what cannot be parsed, show what changed.
